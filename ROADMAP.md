# Photonic — roadmap

Photonic is the shared browser 3D/WebXR rendering engine for the portfolio (Vomitorium, KataPose visualization). Canonical repo: this one. Public mirror: joelmartinez/photonic (MIT). The long-term graduation is npm publication as @codecube/photonic; until then, consumers use the assumed peer checkout (file:../photonic).

## Graduation path to npm

- **D1 — Decoupling audit and plan.** Map every SSG coupling left from the extraction (relative imports into the host site, the Modulation workstream import in src/index.js, webpack-based module discovery, example modules that depend on pieces not extracted). Output: a written plan with an ordered fix list. No code changes.
- **D2 — Decoupling implementation.** Execute the D1 plan: the library imports nothing from any host site, carries its own module loading story, and the examples run standalone against the library alone. Verified by a clean-room check: a fresh folder with only Photonic and its declared dependencies runs an example scene.
- **F1 — Clean overlay rendering.** The video-overlay rendering path from DESIGN.md: crisp resolution-independent overlay graphics composited over a video element, stable frame to frame, styleable, clean by default. Verified with a pose-skeleton-over-video demo scene. The default skeleton style is the KataPose MVP look (Joel, 2026-11-10): bones as translucent outlined cylinders with glowing joint spheres, cyan-blue scheme — simple geometry, no anatomical bone models. The overlay must also support deviation display primitives: per-joint color encoding by offset magnitude, and arrow glyphs showing a 3D offset vector's direction (the KataPose review experiment compares color-only against arrows).
- **F2 — Virtual camera mode.** Emit any scene (including the overlay composite) as a captured MediaStream with a documented consumer pattern; honest labeling of what a browser stream can and cannot do versus an OS-level virtual camera device.
- **P1 — Package readiness.** Exports map, type declarations, README with a working quickstart, standalone examples, version and changelog discipline, and an npm pack dry run whose tarball is inspected file by file. The library must install and run from the packed tarball in a clean folder.
- **⛔ GATE — npm publish.** Publishing happens only on Joel's explicit word, with his npm account credentials through the secure flow. The chain prepares everything up to this gate and stops.
- **C1 — Consumer flip (after the gate).** Every consumer changes its dependency line from the peer checkout to the published version; imports do not change. Each flip is verified through that project's real build. The consumers, per Joel (2026-11-10): the Vomitorium; the KataPose platform builds; **codecube.net** — the Static-Site-Generator replaces the integrated copy Photonic was extracted from, closing the loop (the origin site becomes an ordinary consumer); and **HootCAD** (owlprecision/hootcad), which takes the published package up as its rendering layer when that workstream reaches it.

## Standing rules

The local repo is canonical; the GitHub mirror refreshes by snapshot push from interactive sessions after roadmap-level stages — chain sessions commit locally and never push. npm publishing only on Joel's word. Code comments stay lean.

## Cross-project feature requests (from KataPose, Joel 2026-11-11)

Filed by the KataPose Lab's switch to Photonic, at Joel's direction that the projects ask things of each other. These carry KataPose's portfolio priority while KataPose needs them.

- **F3 — A "not seen" bone style for the 3D stage. Done 2026-11-11.** Photonic has no dashed style, so the Lab renders unseen bones faint. Add a dashed (or equivalently distinct) line style for skeleton bones so a consumer can show absent or low-confidence bones as visibly not-measured in the 3D view. Landed as PhotonicSkeleton in src/PhotonicSkeleton.js: seen bones stay translucent outlined cylinders, a bone touching an unmeasured joint becomes a gray dashed line, and that joint becomes a hollow wireframe sphere; design in design/SKELETON-3D.md, proof in examples/skeleton-demo/, evidence in PROGRESS.md.
- **F4 — Hollow joint markers in the overlay, first-class. Done 2026-11-11.** The Lab currently carries a marked local patch on its vendored copy of PhotonicOverlay to render below-confidence joints as hollow wireframe markers over the video. Upstream that behavior as a supported overlay option so the patch can be deleted. Landed in src/PhotonicOverlay.js with the patch's own geometry, color, and opacity as the default style, on by default and toggleable; design in design/OVERLAY.md, proof in examples/overlay-demo/, evidence in PROGRESS.md.
- **F5 — A depth cue for overlay arrows. Done 2026-11-11.** An offset that points mostly toward or away from the camera projects to a near-invisible 2D arrow. Add a ring cue at the joint (growing or shrinking with the depth offset) so depth misses read clearly in the overlay view. Landed in src/PhotonicOverlay.js: a deviation-colored ring at the joint when at least half the offset lies along the view axis, growing toward the camera and shrinking away under one signed formula; design in design/OVERLAY.md, proof in examples/overlay-demo/, evidence in PROGRESS.md.

Verification for each: the overlay and 3D demos extended to show the new behavior, with the same headless checks the F1 work used. When all three land, the chain stops and reports: the remaining steps (mirror push to GitHub, Lab re-vendoring without the patch) are interactive.

## Cross-project feature requests (from codecube.net integration, 2026-11-11)

Filed by the codecube.net F1 flip at the same standing direction: projects ask things of each other. This one blocks the F1 landing, so it carries the integration project's priority until it lands.

- **F6 — The packaged loader's dynamic import must survive webpack.** PhotonicSceneLoader._loadModule loads scene modules with import(url), where the URL is a runtime value. Webpack, bundling a consumer like codecube.net, replaces that expression import with an empty context that throws "Cannot find module" for every URL, so a webpack-bundled consumer can never load a scene module. The one-line fix is in the package: add the webpackIgnore magic comment beside the existing vite-ignore comment, giving `await import(/* webpackIgnore: true */ /* @vite-ignore */ url)`. Vite and Rollup ignore the unknown comment; webpack then leaves a native import in the output. Evidence: the F1 scratch build in the codecube-net-integration control repo (design/scratch-ssg) reproduced the failure headlessly (host page up, every module load failing with that exact error), and the same build pointed at a locally fixed copy of the package passed the full headless module sequence. A prepared patch sits in that repo at design/patches/photonic-loader-webpackignore.patch. Landing this means the usual upstream route: the change lands in this repo and is pushed to the GitHub upstream, and codecube.net's lockfile then pins the new commit. LANDED 2026-11-11 in the 0.1.1 upstream push, approved by Joel with the codecube.net F1 flip.
