# Photonic — roadmap

Photonic is the shared browser 3D/WebXR rendering engine for the portfolio (Vomitorium, KataPose visualization). Canonical repo: this one. Public mirror: joelmartinez/photonic (MIT). The long-term graduation is npm publication as @codecube/photonic; until then, consumers use the assumed peer checkout (file:../photonic).

## Graduation path to npm

- **D1 — Decoupling audit and plan.** Map every SSG coupling left from the extraction (relative imports into the host site, the Modulation workstream import in src/index.js, webpack-based module discovery, example modules that depend on pieces not extracted). Output: a written plan with an ordered fix list. No code changes.
- **D2 — Decoupling implementation.** Execute the D1 plan: the library imports nothing from any host site, carries its own module loading story, and the examples run standalone against the library alone. Verified by a clean-room check: a fresh folder with only Photonic and its declared dependencies runs an example scene.
- **F1 — Clean overlay rendering.** The video-overlay rendering path from DESIGN.md: crisp resolution-independent overlay graphics composited over a video element, stable frame to frame, styleable, clean by default. Verified with a pose-skeleton-over-video demo scene. The default skeleton style is the KataPose MVP look (Joel, 2026-11-10): bones as translucent outlined cylinders with glowing joint spheres, cyan-blue scheme — simple geometry, no anatomical bone models. The overlay must also support deviation display primitives: per-joint color encoding by offset magnitude, and arrow glyphs showing a 3D offset vector's direction (the KataPose review experiment compares color-only against arrows).
- **F2 — Virtual camera mode.** Emit any scene (including the overlay composite) as a captured MediaStream with a documented consumer pattern; honest labeling of what a browser stream can and cannot do versus an OS-level virtual camera device.
- **P1 — Package readiness.** Exports map, type declarations, README with a working quickstart, standalone examples, version and changelog discipline, and an npm pack dry run whose tarball is inspected file by file. The library must install and run from the packed tarball in a clean folder.
- **⛔ GATE — npm publish.** Publishing happens only on Joel's explicit word, with his npm account credentials through the secure flow. The chain prepares everything up to this gate and stops.
- **C1 — Consumer flip (after the gate).** Every consumer changes its dependency line from the peer checkout to the published version; imports do not change. Each flip is verified through that project's real build. The consumers, per Joel (2026-11-10): the Vomitorium; the KataPose platform builds; **codecube.net** — the Static-Site-Generator replaces the integrated copy Photonic was extracted from, closing the loop (the origin site becomes an ordinary consumer); and **HootCAD** (owlprecision/hootcad), which takes the published package up as its rendering layer when that workstream reaches it.

The local repo is canonical; the GitHub mirror refreshes by snapshot push from interactive sessions after roadmap-level stages — chain sessions commit locally and never push. npm publishing only on Joel's word. Code comments stay lean.

## Cross-project feature requests (from codecube.net integration, 2026-11-11)

Filed by the codecube.net F1 flip at the same standing direction: projects ask things of each other. This one blocks the F1 landing, so it carries the integration project's priority until it lands.

- **F6 — The packaged loader's dynamic import must survive webpack.** PhotonicSceneLoader._loadModule loads scene modules with import(url), where the URL is a runtime value. Webpack, bundling a consumer like codecube.net, replaces that expression import with an empty context that throws "Cannot find module" for every URL, so a webpack-bundled consumer can never load a scene module. The one-line fix is in the package: add the webpackIgnore magic comment beside the existing vite-ignore comment, giving `await import(/* webpackIgnore: true */ /* @vite-ignore */ url)`. Vite and Rollup ignore the unknown comment; webpack then leaves a native import in the output. Evidence: the F1 scratch build in the codecube-net-integration control repo (design/scratch-ssg) reproduced the failure headlessly (host page up, every module load failing with that exact error), and the same build pointed at a locally fixed copy of the package passed the full headless module sequence. A prepared patch sits in that repo at design/patches/photonic-loader-webpackignore.patch. Landing this means the usual upstream route: the change lands in this repo and is pushed to the GitHub upstream, and codecube.net's lockfile then pins the new commit. LANDED 2026-11-11 in the 0.1.1 upstream push, approved by Joel with the codecube.net F1 flip.

## Cross-project feature requests (from codecube.net integration, 2026-11-12)

Filed by the codecube.net Q1 viz quality pass at the same standing direction. These carry the integration project's priority while Q1 needs them. Evidence for both sits in that project's control repo: design/Q1-QUALITY.md (the measured diagnosis) and design/q1/screenshots/ (before screenshots of the live scenes, after screenshots of the prepared site-side step).

- **F7 — Shadows that can actually happen. Done 2026-11-12.** The renderer enables PCF soft shadow maps and the grid floor receives, but no engine light is ever set to cast and no created object is ever set to cast or receive, so no standard scene shows any shadow. Make the default directional light cast with a sane shadow camera and map size, add shadow options to the point and spot light creators and their handles, and set cast and receive flags in the object creators with an opt-out for transparent and emissive objects. Verification: the box and solar-system examples show a soft shadow under the box and planet and moon shadows from a light at the sun, captured as screenshots. Deeper finding from the same session, which makes this a defect and not only a missing default: with every flag set correctly at runtime on the shipped build (light castShadow on with a 2048 map, cube cast and receive on, floor receive on, shadow map enabled), the cube IS rendered into the light's shadow map (verified by reading the map's center pixels back) yet no receiving surface ever darkens, and the same failure occurs with a brand-new light, plane, and cube created directly from the scene's own Three.js instance inside a Photonic page, while a minimal standalone Three.js page with identical settings renders the shadow correctly (evidence captures in the integration repo at design/q1/diagnostics/). So something in the Photonic scene's construction or render loop defeats shadow receiving; root cause not isolated in the filing session, and isolating it is part of this request's work. Resolution (2026-11-12): the defaults half landed exactly as requested (default directional light casts at 2048 with a stage-fitted shadow camera, cast/receive in the object creators with the transparent/emissive opt-out, shadow options and handle switches on the point and spot creators), verified by a no-hand-wiring capture in design/evidence/f7-box-shadow.png. The defect half did not survive bisection: shadow receiving works in the shipped build, in this repo, and in the new-light/new-geometry pattern, and the filing session's empty captures are explained by its camera sitting on the light's side of the caster, where the shadow falls behind the caster and out of view; the full root-cause record is in design/F7-SHADOWS.md.
- **F8 — Ambient occlusion and light grading as an engine output step. Done 2026-11-12.** The renderer draws directly with no post-processing and no tone mapping, so scenes clip to flat saturated color and contact areas have no depth. Add an optional composer chain (GTAO or SSAO from the Three.js r170 addons, plus an output pass), ACES filmic tone mapping with an exposure control on the renderer or scene, and a pixel-ratio cap near 2. Verification: the same example scenes with the step on and off, captured as screenshots, with the frame cost stated. Until F7 and F8 land, codecube.net carries a marked temporary site-side version of the grading and shadow switches in its /viz host page and scene modules; that workaround is deleted when these land. Resolution (2026-11-12): landed in src/PhotonicRenderer.js with scene-level controls in src/PhotonicScene.js — ACES filmic grading is on by default with setExposure and setToneMapping on the renderer and the scene, the pixel ratio is capped at 2 with setPixelRatioCap, and an opt-in composer chain (render pass, GTAO, output pass) turns on through enablePostProcessing or a construction option, tunes through setPostProcessingOptions, reports through getPostProcessingInfo, and steps aside while XR is presenting. Verified headlessly: the box and solar-system examples captured with the chain off and on (design/evidence/f8-box-off.png, f8-box-on.png, f8-solar-off.png, f8-solar-on.png; contact samples darken only where objects meet the floor, open floor unchanged), a corner probe pair (f8-ao-probe-off.png, f8-ao-probe-on.png) where the occlusion is plainly visible, an exposure sweep that moves mean luminance, a 3x-display check that holds the ratio at the cap, and a raw-Three.js control page that reproduces GTAO's faint showing on a lone box, which separates scene character from engine wiring; frame cost is stated in design/F8-GRADING-AO.md, with the full record there.

## Added 2026-11-12 (Joel, interactive)

- **F9 — Ambient occlusion that looks like occlusion. Done 2026-11-12.** Joel reviewed the F8 corner probe and his read was exact: the screen-space pass darkens a band of about the same width along every edge and seam, which reads as a gradient pasted on the geometry rather than light being blocked (his words: kind of good, not super realistic). Upgrade in three parts, in this order. (1) Baked occlusion for static scenes: compute occlusion from the real geometry by ray casting at scene build time (per-vertex or into a texture; the Vomitorium project's baked arena is the in-house precedent for how much more legitimate this reads), so a corner gets a deep wide soft pool, an object's contact patch matches its actual size, and open floor stays clean. (2) Retune the screen-space pass (F8's GTAO chain) down to the job it is good at — contact darkening for things that move: a wider radius that fades with distance, a softening/denoise pass so it is never a hard band, and an intensity ceiling that never crushes toward black. (3) Keep the balance honest in the defaults: real shadows (F7) do the main grounding work and occlusion is the garnish, not the meal. Verification: the same corner probe scene as F8's evidence (design/evidence/f8-ao-probe-on.png is the "before"), re-captured with the baked and retuned results, plus the box and solar-system examples and one case with a moving object proving the dynamic pass still earns its place; frame and bake costs stated. Chain order: this follows the DOCS step. Resolution (2026-11-12): landed as scene.bakeAmbientOcclusion in src/PhotonicBakedAO.js and src/PhotonicScene.js — hemisphere ray casts from the real geometry at build time, per-vertex over tessellated authored planes and boxes and the objects, plus a ray-cast ground texture that carries contact patches onto the default floor, with an exclude list that keeps moving objects out of the bake entirely — and the GTAO chain retuned in src/PhotonicRenderer.js (radius 0.9 with distance falloff, the Poisson denoise driven wider and exposed as options, blend default 0.55 under a hard 0.85 ceiling). Verified headlessly: the rebuilt corner probe's seam floor drops from about 144 to 53.7 baked while open floor is unchanged at 146 and the wall shading dies out with height instead of banding (design/evidence/f9-ao-probe-baked.png, with gtao-only and combined captures beside it), the box example's floor gains a footprint-shaped patch on the light side (137.1 to 103.2), the solar-system bake leaves an open scene almost untouched (mean visibility 0.99), and an excluded moving box leaves no baked patch at either of its positions while the retuned chain alone darkens its new contact (146 to 141.2) and nothing else. Bake cost about 0.2 to 0.9 seconds across the test scenes, frame costs stated with their rig in design/F9-AO.md, which carries the full record.
