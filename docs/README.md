# Photonic documentation site

This folder is a Chloroplast documentation site, following the same pattern as the Modulator library's docs: `SiteConfig.yml` at this level, templates in `templates/`, markdown source pages and assets in `source/`, and a menu in `source/menu.md`. The workflow in `.github/workflows/docs.yml` builds the site with the Chloroplast docs action and publishes it to GitHub Pages at https://joelmartinez.github.io/photonic/ — the matching address for this repo.

The pages are the home page (with the quickstart), install, concepts, library usage, and features. Every page that shows a demo runs the real library in the reader's browser, per Joel's direction that live examples are required: the demos are plain per-site integrations, with the demo markup in the markdown body, the demo scripts in `source/assets/demos/`, and a copy of the library and its dependencies vendored in `source/assets/photonic/`. No Chloroplast engine features were needed or added — the engine copies the assets through, which is all the pattern asks of it.

One mechanical wrinkle matters when refreshing the vendored copies: Chloroplast lowercases every output filename, so a vendored file named `PhotonicScene.js` would be served as `photonicscene.js` while the library's own imports still ask for the mixed-case name, and the demo's module graph would fail on case-sensitive hosting. The vendored tree is therefore stored lowercased, with its relative and Three.js addons import specifiers lowercased to match. `docs/refresh-vendored.mjs` rebuilds the whole vendored tree from `src/`, `examples/modules/`, and `node_modules` in that normalized form; run it from the repo root after any library release (`node docs/refresh-vendored.mjs`) instead of copying files by hand. Only the addons the library actually imports are vendored, not the whole Three.js examples tree.

To verify the site locally, build it with the Chloroplast tool (`chloroplast build --root docs --out docsout`) and serve the output from a `/photonic/` subpath, which is the shape GitHub Pages serves it in. The build that shipped this site was verified exactly that way, with a headless browser driving every page: all demos executed the vendored library (the quickstart scene ticking, the authoring demo's exposure slider and ambient-occlusion toggle working, the loader switching scene modules by name, and the overlay reporting its hollow joints and depth rings), with no page errors and no failed requests for any site file.
